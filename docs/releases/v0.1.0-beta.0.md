# Glass Terminal v0.1.0-beta.0

> 不装远程 IDE，不使用隐藏 Shell，人与 AI 共用一个真实终端。

这是 Glass Terminal 的首个 Beta 版本。相较 `v0.1.0-alpha.2`，本版本已经从可运行的 Alpha 原型发展为功能基本完整的 Windows-first 可见远程 Agent 工作台，接下来将重点转向更多真实设备、网络和干净 Windows 环境下的兼容性与稳定性验证。

## 本版本亮点

### 🖥️ 面向远程设备的共享可见终端

- Generic Provider 与用户共用同一个本地 PTY 或 SSH Shell，AI 命令只执行一次，不创建第二条隐藏 Shell 或 SSH 连接。
- 原始实时输出直接进入 xterm：编译、安装、Docker、CUDA、设备日志、烧录工具、交互提示和 Ctrl+C 都发生在用户正在看的终端中。
- 目标端通常只需已有的 SSH/SFTP，无需部署 VS Code Server、模型 SDK 或常驻 Agent，适合 Jetson、树莓派、ARM 小电脑、边缘主机和连接单片机/JTAG/串口设备的控制主机。
- 命令默认逐条审批，也可在明确确认后启用 Full Takeover；用户可以随时人工接管。

### 🪟 PowerShell Shell Integration

- 完整移除 PowerShell AI 命令的可见 `__AI_TERMINAL_*` 信封和基于屏幕文本猜测的缩放过滤。
- 本地及 SSH PowerShell 现在使用会话级 Shell Integration，通过不可见、带随机 nonce 的 OSC 生命周期事件获得命令边界、退出码和 cwd。
- 用户与 AI 继续共享同一个长生命周期 PowerShell PTY；不会修改远端 Profile，也不会落地安装脚本。
- 快速、大幅缩放时可见 VT 流保持原样，避免历史命令泄漏、重复输出、正常内容被擦除和大量空行。

### 🧠 可持续的长会话

- 新增圆形上下文占用进度，Generic Provider 在安全阈值自动压缩较早历史，并为模型输出和工具调用预留空间。
- 使用经本地校验的结构化摘要；失败可重试并有确定性降级，近期完整交互和当前请求保持原文。
- 新增可审阅、编辑、合并和 Pin 的有界记忆卡片，重要约束、决策和待办不会只依赖模型自行记住。
- 原先的固定轮数上限改为长任务检查点间隔；达到间隔会保存、刷新上下文并继续同一任务，不再关闭终端。
- 终端历史采用增量游标，Assistant 文本使用独立流式 IPC，降低长会话的重复传输与渲染负担。

### 📁 Workspace 与远程文件安全

- Generic Provider 只获得当前 Turn 注入的 `terminal_execute` 和 `workspace_*` 工具；Harness 不持有自己的 PTY、SSH、SFTP 或文件系统客户端。
- Workspace 支持关闭、只读、绑定根读写和显式确认的 Full Filesystem Access；权限与 Session、Host、终端、Provider 和 Workspace Root 绑定，发生变化即失效。
- 文件读取、搜索、枚举和写入均有大小、数量、深度、时间与上下文预算；大目录不再无界整体物化。
- Shell 感知策略会阻止 `Get-Content`、`cat`、`find` 等命令绕过已授权的 Workspace 文件工具；不能等价转换的操作必须单次确认。
- SSH 文件操作复用当前终端的 SSH 连接和 SFTP 子系统，并校验同一 Host；新增 hardlink、fsync、posix-rename 能力检测及严格/兼容发布策略。

### 🔐 备份、凭据与审计

- Provider API Key 和 SSH 凭据仍保存在 AES-256-GCM 文件密钥库中，不进入模型上下文或普通日志。
- 包含凭据的 `.aitbak` / `.aithosts` 导出现在必须使用至少 12 字符口令整包加密；文件名和内部结构一并保护。
- 导入先在 staging 中完成格式、路径、大小和完整性校验，再事务式提交；失败时回滚，旧版明文凭据备份必须显式确认风险。
- Workspace 操作保留有界、脱敏的意图与结果审计；命令及实际输出继续保存在共享终端历史中。

### ✨ UI 与连接体验

- 重新整理会话栏和 AI 对话布局，主机、会话和消息操作改为紧凑图标，减少大型按钮占用。
- 没有终端 Tab 时不再显示无效 AI 面板；消息可读性、工具活动和上下文状态更清晰。
- 保存过的私钥连接会先无感尝试，只有确实需要口令时才弹窗。
- 修复生产构建后 `npm start` 只出现空窗口的问题。

## Agent 后端

- **Generic Provider：**通过 LangChain 接入 DeepSeek、GLM、MiniMax、OpenAI 等 OpenAI-compatible API；命令进入同一个可见终端，文件操作进入受控 Workspace/SFTP 工具。
- **Codex App Server 原生模式：**支持官方 App Server 的登录、账号、模型、推理强度、Thread/Turn、流式输出和内建工具；可以按授权读取当前终端上下文。

> 当前 Codex App Server 原生模式仍使用 Codex 自己的本地工作区与内建 Shell，不会控制远程公共终端。共享终端执行卖点目前属于 Generic Provider 路径。

## 升级说明

- 可以从 `v0.1.0-alpha.2` 直接升级，用户数据目录仍为 `%APPDATA%\glass-terminal\`。
- Host store v2 和终端日志索引 v1 会在受支持的读取路径中自动迁移；原始会话日志保留。
- 升级前仍建议先通过设置页导出不含凭据的配置备份；如需包含凭据，请设置并妥善保管备份口令。
- 绿色版不内置 Codex CLI。使用 Codex App Server 时，需要从 PATH 自动检测或在界面中手动选择官方 `codex.exe`。

## Beta 阶段说明

- 当前为 Windows-first 绿色版，尚未提供代码签名，Windows SmartScreen 可能显示未知发布者提示。
- 仍需扩大干净 Windows、不同 OpenSSH/PowerShell 版本、弱网及更多真实 Jetson/ARM 主机的验证范围。
- 超大单层目录和并发远端改名仍受 SFTP 协议及服务器能力限制；本版本更适合小型和中型工程。
